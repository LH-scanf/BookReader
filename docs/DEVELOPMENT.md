## 1. 产品目标

BookReader 是一款面向 Windows 的本地优先 EPUB 阅读器。

核心目标：

- 简洁的现代卡片式书库。
- 阅读时尽量减少界面干扰。
- 同时支持分页和连续滚动。
- 图书、阅读进度以及未来的书签、批注和高亮可以通过 OneDrive 等同步目录跨设备同步。
- 最终提供可独立运行的 EXE、NSIS `setup.exe` 和 MSI 安装包。

## 2. 已确认的产品决策

- 平台：第一阶段只支持 Windows。
- 导入行为：默认将 EPUB 复制进书库目录。
- 书库目录：首次使用时可选择，之后允许迁移。
- 侧边栏：可展开和隐藏；包含“我的书库”“已读”，底部始终保留“设置”。
- 打开图书：在同一个桌面窗口中从书库切换至阅读页，不创建新的 Windows 窗口。
- 阅读操作：支持点击左右区域、界面按钮、鼠标滚轮和键盘。
- 无封面图书：自动生成文字封面。
- 高亮只保留一种柔和样式；针对原文的感悟统一汇总到每本书的“整书笔记”。
- 云端只负责同步普通文件；BookReader 监听目录变化并自动加载 `updatedAt` 最新的阅读进度，不弹出设备冲突确认。
- DRM：MVP 只支持无 DRM 的 EPUB 2 / EPUB 3。

## 4. 数据与同步设计

书库目录是可被 OneDrive、Dropbox 或其他文件同步工具管理的普通目录：

```text
BookReaderLibrary/
├── books/
│   └── {book-id}/
│       ├── book.epub
│       ├── cover.*
│       └── metadata.json
├── progress/
│   └── {book-id}/
│       └── {device-id}.json
├── annotations/
│   └── {book-id}/
│       └── {annotation-id}.json
├── notes/
│   └── {book-id}.json
├── settings/
│   ├── roaming.json
│   └── devices/{device-id}.json
└── library-version.json
```

原则：

- 不修改原 EPUB 内容。
- SQLite 只作为本地可重建索引，不直接放进同步目录。
- 阅读位置以 EPUB CFI 为准，同时保存章节和百分比。
- 每台设备写独立进度文件，读取时自动采用 `updatedAt` 最新的记录。
- 高亮与原文感悟按记录 ID 合并，删除使用 `deletedAt` 墓碑字段，避免旧设备恢复已删除数据。
- 一本书在界面上只有一个整书笔记，其中包含读后总结和多条“原文 + 感悟”；底层摘录仍按记录拆分以降低同步冲突。
- 所有同步 JSON 使用“临时文件写入 + 原子替换”，防止退出或同步中断留下不完整文件。
- 所有 JSON 包含 `schemaVersion`，支持未来迁移。

## 5. 技术架构

- 桌面外壳：Tauri 2
- 前端：React + TypeScript + Vite
- EPUB 渲染：epub.js
- 桌面文件选择：Tauri Dialog Plugin
- 文件导入与 EPUB 元数据解析：Rust
- 本地索引：后续接入 SQLite
- 同步来源：用户选择的普通文件夹

## 7. 运行与打包说明

开发启动：

```powershell
npm run tauri dev
```

也可以直接双击项目根目录的 `Start-BookReader.cmd`。启动器会检查 1420 端口、清理本项目遗留的 Vite 进程，并在应用已经运行时给出明确提示。

开发模式必须保持命令窗口运行。`src-tauri/target/debug/bookreader.exe` 会连接开发服务器，不能作为独立成品直接双击。

生成可独立运行版本：

```powershell
npm run tauri build
```

预计输出目录：

```text
src-tauri/target/release/bookreader.exe
src-tauri/target/release/bundle/nsis/
src-tauri/target/release/bundle/msi/
```

## 9. 本轮稳定性说明

- EPUB 导入命令放入后台阻塞线程执行，避免解析和复制期间冻结界面；多选导入会并行处理。
- 主题切换同时更新 EPUB.js 样式覆盖、阅读容器和 iframe 文档根节点，兼容 EPUB 自带的背景色规则。
- 滚动模式只渲染当前章节，不再在滚动途中追加相邻章节；目录跳转会等待章节完成显示后再更新位置。
- 图书卡片更多菜单支持打开、标记已读/未读和从书库删除；删除前会再次确认。
- 真实 EPUB 回归测试已覆盖全文搜索、临时跳转返回、整书总结、高亮归档和小窗口目录滚动；浏览器控制台无错误。
- Rust 自动化测试覆盖 JSON 备份恢复、跨设备最新进度选择和 EPUB 元数据/封面提取。

## 10. 已知技术债务

- 当前通过 Tauri IPC 以 Base64 传递整本 EPUB；大型图书需要改为流式或自定义协议读取。
- epub.js 已拆分为按需加载代码块，但仍需测试复杂 EPUB 的样式隔离。
- 切换书库目录目前不会自动复制旧书库，正式迁移功能属于阶段 C。
- 重复导入识别和损坏 EPUB 的修复尚未实现。

## 12. v0.2.2 阅读布局修复（待用户验收）

用户反馈 v0.2.1 仍出现横向滚动条，且分页正文发生左右裁切；上一轮样例结果不能代表实际问题已经解决。

- 分页模式不再限制章节 iframe 的完整横向宽度，也不覆盖 epub.js 计算的正文宽度和分页内边距，避免破坏 CSS 分栏及翻页步长。
- 滚动模式仅由实际的 `.epub-container` 承担竖向滚动；在这一层禁用横向滚动并固定滚动条占位，使正文按照扣除滚动条后的宽度排版。
- 两种模式分别设置尺寸约束，避免滚动模式的限制污染分页模式；移除短窗口中强制 430px 正文高度。
- 按用户要求仅修改与构建，不运行自动化测试、浏览器测试或启动应用；构建产物交用户验收，暂不发布。
