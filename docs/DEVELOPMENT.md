# BookReader 产品与开发文档

## 1. 产品目标

BookReader 是一款面向 Windows 的本地优先 EPUB 阅读器。

核心目标：

- 简洁的现代卡片式书库。
- 阅读时尽量减少界面干扰。
- 同时支持分页和连续滚动。
- 图书、阅读进度以及未来的书签、批注和高亮可以通过 OneDrive 等同步目录跨设备同步。
- 最终提供可独立运行的 EXE、NSIS `setup.exe` 和 MSI 安装包。

## 2. 已确认的产品决策

- 平台：第一阶段只支持 Windows。
- 导入行为：默认将 EPUB 复制进书库目录。
- 书库目录：首次使用时可选择，之后允许迁移。
- 侧边栏：可展开和隐藏；包含“我的书库”“已读”，底部始终保留“设置”。
- 打开图书：在同一个桌面窗口中从书库切换至阅读页，不创建新的 Windows 窗口。
- 阅读操作：支持点击左右区域、界面按钮、鼠标滚轮和键盘。
- 无封面图书：自动生成文字封面。
- MVP 暂不实现书签、批注和高亮，但同步格式需要为这些数据预留升级空间。
- DRM：MVP 只支持无 DRM 的 EPUB 2 / EPUB 3。

## 4. 数据与同步设计

书库目录是可被 OneDrive、Dropbox 或其他文件同步工具管理的普通目录：

```text
BookReaderLibrary/
├── books/
│   └── {book-id}/
│       ├── book.epub
│       ├── cover.*
│       ├── metadata.json
│       └── progress.json
├── annotations/
│   └── {book-id}.json
├── user-settings.json
└── library-version.json
```

原则：

- 不修改原 EPUB 内容。
- SQLite 只作为本地可重建索引，不直接放进同步目录。
- 阅读位置以 EPUB CFI 为准，同时保存章节和百分比。
- 阅读进度冲突由 `updatedAt` 较新的记录获胜。
- 未来批注按记录 ID 合并，删除使用 `deletedAt` 墓碑字段，避免旧设备恢复已删除数据。
- 所有 JSON 包含 `schemaVersion`，支持未来迁移。

## 5. 技术架构

- 桌面外壳：Tauri 2
- 前端：React + TypeScript + Vite
- EPUB 渲染：epub.js
- 桌面文件选择：Tauri Dialog Plugin
- 文件导入与 EPUB 元数据解析：Rust
- 本地索引：后续接入 SQLite
- 同步来源：用户选择的普通文件夹

## 7. 运行与打包说明

开发启动：

```powershell
npm run tauri dev
```

也可以直接双击项目根目录的 `Start-BookReader.cmd`。启动器会检查 1420 端口、清理本项目遗留的 Vite 进程，并在应用已经运行时给出明确提示。

开发模式必须保持命令窗口运行。`src-tauri/target/debug/bookreader.exe` 会连接开发服务器，不能作为独立成品直接双击。

生成可独立运行版本：

```powershell
npm run tauri build
```

预计输出目录：

```text
src-tauri/target/release/bookreader.exe
src-tauri/target/release/bundle/nsis/
src-tauri/target/release/bundle/msi/
```

## 9. 本轮稳定性说明

- EPUB 导入命令放入后台阻塞线程执行，避免解析和复制期间冻结界面；多选导入会并行处理。
- 主题切换同时更新 EPUB.js 样式覆盖、阅读容器和 iframe 文档根节点，兼容 EPUB 自带的背景色规则。
- 滚动模式只渲染当前章节，不再在滚动途中追加相邻章节；目录跳转会等待章节完成显示后再更新位置。
- 图书卡片更多菜单支持打开、标记已读/未读和从书库删除；删除前会再次确认。
3. 增加删除图书和更多操作菜单。
4. 实现真正的书库迁移，而不是仅切换目录。
5. 监控同步目录变化并处理进度冲突。

## 9. 已知技术债务

- 当前通过 Tauri IPC 以 Base64 传递整本 EPUB；大型图书需要改为流式或自定义协议读取。
- epub.js 已拆分为按需加载代码块，但仍需测试复杂 EPUB 的样式隔离。
- 切换书库目录目前不会自动复制旧书库，正式迁移功能属于阶段 C。
- 书籍删除、重复导入识别和损坏恢复尚未实现。
