# PWA 首版需求与开发前基线

日期：2026-08-26

## 1. 开发前基线

- 基线版本：`0.2.4`；对应 Git 标签：`v0.2.4`。
- 本次归档现有桌面端修复与需求讨论，不实现 PWA 功能、不改动版本号、不推送远端、不创建线上发布。
- 版本标签用于固定开发前源码，不代表功能验收通过。既有构建与待验收状态见 [Bug 修复时间线](bugfix-timeline.md)。本次仅检查 Git 差异和版本一致性，不重新构建、运行测试或启动程序。
- 后续开发从此基线创建独立开发分支；不移动或覆盖基线标签。PWA 的发布版本号在进入开发时另行确定。

## 2. 用户已确认的首版需求

- 个人微软账号、个人 OneDrive；尚未在 OneDrive 建立书库目录。
- iPhone 使用 iOS 17.5，作为首版真机验收目标；书库按 100 本以内设计，具体文件大小仍需用实际 EPUB 验证。
- 手机支持阅读及阅读进度双向同步；手机笔记、高亮先查看，编辑后续实现。
- 手机首版需要导入 EPUB 和删除云端图书。
- 删除采用软删除：先隐藏并同步删除标记，暂不永久清除 EPUB、进度、批注和整书笔记，保留恢复余地。
- “移除本机下载”与“从书库删除”是不同操作；前者不能删除云端数据。
- 开发前先提交现有 Git 改动并固定版本。

## 3. 架构与行为方案

以下为讨论中的实施方案，尚未实现；具体接口与协议在开发阶段细化。

- 在现有仓库共用 React、TypeScript、Vite、epub.js，不复制独立 PWA 项目。
- 抽出 `LibraryProvider`，由 `TauriProvider` 和 `WebProvider` 实现；文件读写、平台能力、数据变化通知和生命周期处理一起隔离。
- 仅 Web 构建启用 `vite-plugin-pwa`；Tauri 不注册 Service Worker，Web 不执行 Tauri 接口。
- 应用资源使用 Service Worker / Cache Storage；EPUB 优先使用 OPFS，可降级 IndexedDB Blob；索引、阅读数据、待上传队列与同步游标使用 IndexedDB。
- 先同步书库索引，EPUB 按需下载；提供离线保留和本机缓存移除入口。
- 导入先校验并持久保存到本机，再排队上传；上传中断和重试不能使其他设备误读不完整书籍。
- 进度和操作在使用过程中持续落盘，不依赖退出时保存。同步由启动、回到前台、恢复联网、前台定时及手动操作触发，不承诺锁屏或关闭后的持续后台同步。
- 明确区分已保存到本机、等待同步、上传中、已同步、离线、登录过期和失败状态。
- 第一笔云端写入前实现持久化队列和重试；同一操作重试不得产生重复导入或使已删除图书复活。
- 阅读进度延续每设备独立文件；不以最大百分比判定最新位置，保留本机回流和远程刷新防回跳逻辑。
- 桌面端同步升级软删除协议；旧版桌面端不具备该保护，不能承诺与其完整双向兼容。
- 手机笔记编辑不纳入首版；后续实现时需处理同条批注及整书总结的并发修改，不能静默覆盖。

## 4. OneDrive 与部署方案

- 建议使用 Graph `approot` 对应的应用专用目录及委托 `Files.ReadWrite.AppFolder` 权限；实际目录由 API 返回，不硬编码路径。应用注册名称和最终书库路径在接入阶段确定。
- 桌面端初期继续通过 Windows OneDrive 客户端同步本地书库目录；手机通过 Microsoft Graph 访问同一云端书库。
- 若迁移现有本地书库，整体复制目录并保留图书 ID、进度和笔记；验证前保留原目录，不以重新导入 EPUB 代替迁移。
- 使用 `@azure/msal-browser`，SPA 授权码 + PKCE；前端不保存客户端密钥。
- GitHub → Cloudflare Pages → `npm run build` → `dist/`；托管应用代码，不把私人 EPUB、笔记或令牌放入仓库和部署产物。
- 建立 HTTPS 测试地址后尽早验证 iPhone 的登录回跳、安装、离线启动、EPUB 排版、长按选字及输入法行为。
- 本次未注册微软应用、创建 OneDrive 目录或 Cloudflare 项目，也未连接或发布到任何云端服务。

## 5. 开发顺序

1. 固定数据协议：导入完成状态、软删除与恢复、设备 ID、队列、版本及旧书库兼容。
2. 抽出 Provider，保持现有桌面功能，隔离 Tauri 依赖。
3. 实现 Web 本地导入、阅读、进度保存与软删除。
4. 完成手机 UI、触摸和安全区适配，接入 PWA，并开始 iPhone 真机验证。
5. 实现微软登录、应用目录初始化和现有书库接入。
6. 实现书库读取、按需缓存、导入上传、增量拉取和进度双向同步。
7. 完善跨设备软删除、恢复、队列失败重试和并发保护。
8. 完成正式部署与桌面、手机完整往返验收。

## 6. 首版验收重点

- 桌面导入 → 手机可见并下载 → 断网重启后可继续阅读。
- 手机离线阅读 → 回到在线前台完成同步 → 桌面续读；反向流程同样验证。
- 手机导入 → 上传完成 → 桌面可正常打开；断网重试不重复生成书籍。
- 手机或桌面软删除 → 另一端同步隐藏；文件暂留，恢复路径需验证。
- 移除本机缓存不影响云端图书和笔记；删除与待上传进度冲突时不复活图书。
- 缓存空间不足、登录过期、请求失败和应用更新有明确提示，不静默丢弃待上传数据。
- 原桌面端分页、滚动、笔记和进度防回跳行为不因 Provider 重构退化。
